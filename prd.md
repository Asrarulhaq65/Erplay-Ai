PRODUCT REQUIREMENT DOCUMENT (PRD) - FINAL VERSIONProject Name: Retail ERP BY Arul
Target Environment: Laravel, Laragon (Localhost), phpMyAdmin, Bootstrap 5 (Compact -sm)Design Philosophy: Minimalist, Compact, High-Speed Data Entry, Protective Against Wrong Inputs, Pastel Blue Palette.
1. PROJECT OVERVIEW & ARCHITECTURE GOALSSistem ini adalah aplikasi ERP Retail Multi-Tenant (SaaS-Ready) yang mengelola inventaris skala besar (>1.000 produk), rantai pasok (Supplier & Pembelian), manajemen pelanggan dengan multi-tier pricing, manajemen keuangan, serta dilengkapi dengan Dual-Model POS (Point of Sale) dan Modul Rekap Penjualan Tingkat Lanjut.Core Constraints for Vibe Coding Agent:Multi-Tenancy: Setiap tabel utama wajib menyertakan dan memfilter berdasarkan toko_id. Data antar tenant terisolasi secara mutlak.UI Footprint: Gunakan utilitas Bootstrap -sm (form-control-sm, btn-sm, table-sm, padding minimal) untuk menghemat ruang layar (compact & dense).Color Palette: Dominasi warna latar bersih (putih/abu-abu terang) dengan aksen Soft Pastel Blue (#EBF3F5 sampai #A0C4DF) untuk komponen primer, header tabel, dan status aktif.
2. SYSTEM MODULES & FUNCTIONAL REQUIREMENTSMODULE 
1: Tenant & RBAC (Role Based Access Control)Tenant Management (toko): Menyimpan profil toko (nama, alamat, logo, slogan struk).User Management & Roles:Setiap user terikat pada satu toko_id dan satu role_id.Roles: Super Admin (Manajemen Tenant), Owner (Akses semua laporan & finansial), Gudang (Hanya modul Produk & Pembelian), Kasir (Hanya modul POS & Laporan Shift).Protective Feature: Fitur Soft Toggle is_active. Jika is_active = 0, user otomatis ter-logout dan tidak bisa login kembali.MODULE 
2: Master Barang & Pengelompokan Hirarki (Inventory)Product Hierarchy Structures:Kelompok (kelompok_produk): Tingkat tertinggi/Departemen (Contoh: Alat Tulis, Sembako).Kategori (kategori_produk): Sub-kategori yang terikat pada kelompok_id (Contoh: Kelompok Alat Tulis memiliki Kategori Buku, Pulpen, Penghapus).Data Fields Produk (produk): Barcode (Indexed/Unique per tenant), Nama Produk, kategori_id (Relasi ke Sub-Kategori), Satuan (Pcs/Pack/Dus), Harga Modal, Harga Jual Umum, Harga Jual Member, Harga Jual Rekan, Harga Jual Motoris, Stok, Stok Minimum.UI/UX Requirement (Chained Dropdown):Pada form input produk, saat user memilih Kelompok, dropdown Kategori di bawahnya secara otomatis terfilter (menggunakan AJAX) hanya menampilkan kategori yang valid di bawah kelompok tersebut.Protective Visual: Tampilkan tabel produk yang padat (table-sm). Berikan conditional class table-danger (menggunakan warna merah pastel lembut) pada baris produk jika jumlah stok $\le$ stok_minimum.
MODULE 3: Pengelolaan Pelanggan & Multi-Tier PricingCustomer Directory (pelanggan): Mencatat profil pelanggan tetap per toko.Data Fields: Kode Pelanggan (Unique per toko), Nama, No Telepon, Alamat, dan Status Pelanggan (Umum, Member, Rekan, Motoris).Price Mapping Logic: Status pelanggan ini yang akan menentukan secara otomatis harga mana yang ditarik oleh sistem saat transaksi POS berlangsung.
MODULE 4: Supplier & Pembelian Barang (Restock)Supplier Directory: Mencatat data vendor pemasok barang.Faktur Pembelian (pembelian & pembelian_detail):Mencatat aktivitas kulakan barang dari supplier.Pilihan Metode Pembayaran: Tunai atau Kredit. Jika Kredit, kolom jatuh_tempo wajib diisi dan status pembelian di-set Hutang.Automation Trigger (On Submit Faktur):Menambah kuantitas stok pada tabel produk.Memperbarui nilai harga_modal pada tabel produk menggunakan pendekatan Last Cost (mengikuti harga beli terbaru).Membuat baris baru secara otomatis pada tabel log_stok dengan tipe Masuk_Barang.Jika dibayar Tunai, otomatis memotong saldo kas dan mencatatnya ke tabel arus_kas dengan kategori 'Pembelian Stok'.
MODULE 5: Keuangan & Laporan (Financial Analytics)Buku Kas Digital (arus_kas): Mencatat otomatis semua uang masuk (Penjualan) dan uang keluar (Pembelian, Operasional).Laporan Penting yang Wajib Disediakan:Laporan Laba Rugi Real-Time: Menghitung keuntungan bersih harian/bulanan dengan rumus: $\sum (\text{harga\_satuan\_terjual} - \text{harga\_modal}) \times \text{qty}$.Laporan Produk Terlaris (Fast Moving): Urutan produk berdasarkan volume penjualan terbanyak.Laporan Analisa Kelompok (Department Performance Report): Menampilkan performa penjualan dan profitabilitas per Kelompok Barang (Contoh: Mengetahui total profit dari kelompok Alat Tulis vs Sembako).
3. DUAL-MODEL POS (POINT OF SALE) SPECIFICATIONSistem wajib menyediakan dua halaman atau mode POS yang berbeda:
MODE 1: Standard POSLayout retail konvensional menggunakan visualisasi grid produk atau list dengan kolom pencarian standar, cocok untuk penggunaan kasir umum atau perangkat layar sentuh.
MODE 2: Custom Quick-Entry POS (High-Speed & Zero Mouse Click)Mode khusus yang didesain untuk data entry super cepat, tanpa foto produk, dan sepenuhnya dikendalikan oleh keyboard (keyboard-driven).UX Logic Flow & Automations (Wajib Diikuti Agen Koding):Page Load Focus: Saat halaman POS dimuat, kursor otomatis aktif (autofocus) di input Nama/Kode Pelanggan. Input ini berupa live-search dropdown yang bisa diketik.Default Value jika kasir langsung menekan Enter tanpa mengetik adalah pelanggan "Umum" dengan status tingkatan harga Umum.State Memory (Mengunci Status Pelanggan): Begitu pelanggan dipilih (misal: "Budi" dengan status Motoris), sistem mengunci status tersebut di dalam state JavaScript halaman POS.Navigation Shift: Menekan tombol Enter pada input Pelanggan akan langsung memindahkan fokus kursor ke input Pencarian Produk.Predictive Dropdown (Live Search Produk):Saat user mengetik minimal 2 karakter (misal: "Ste"), sistem memicu pencarian asinkronus (AJAX) ke backend untuk mencocokkan nama produk atau barcode.Hasil pencarian muncul dalam bentuk dropdown melayang (overlay) di bawah input, tanpa merusak layout halaman.Dynamic Pricing Selection:User memilih produk menggunakan tombol Arrow Down/Up dan menekan Enter untuk memilih produk teratas.Setelah Enter ditekan pada produk, sistem secara otomatis mengecek status pelanggan yang sedang terkunci (Poin 2). Jika statusnya Motoris, maka sistem otomatis mengambil nilai harga_jual_motoris dari produk tersebut untuk diaplikasikan ke keranjang.Tampilkan badge kecil Bootstrap berwarna pastel blue di samping input untuk menunjukkan info harga aktif (Contoh: [Motoris Mode: Rp 8.500]).Quantity Input: Fokus kursor otomatis pindah ke input Qty. Angka di dalam input Qty default-nya adalah 1 dan langsung ter-blok seluruhnya (highlighted), sehingga kasir bisa langsung mengetik angka baru tanpa perlu menghapus angka 1 terlebih dahulu.Append and Reset Loop:Menekan Enter pada input Qty akan memasukkan item ke keranjang belanja di sisi klien.Setelah berhasil di-append, sistem otomatis mengosongkan input Pencarian Produk dan mengembalikan fokus kursor ke input Pencarian Produk tersebut. Kasir langsung siap mengetik produk kedua tanpa menyentuh mouse.Metode Pembayaran POS Custom (Payment Type):Pada modal / panel pembayaran POS Custom, sistem menyediakan opsi metode pembayaran berikut:Tunai: Pembayaran kas langsung (menghitung nominal uang bayar dan kembalian).Kredit (Tempo): Status tagihan di-set Belum Lunas dan otomatis masuk ke pencatatan piutang dagang.Digital Payment: Pencatatan administratif untuk transaksi non-tunai (Transfer, QRIS, dll). Tidak ada integrasi payment gateway pihak ketiga. Cukup menyediakan input teks opsional untuk mencatat nomor referensi/ID transaksi bank untuk kebutuhan audit internal.Sistem Validasi Protektif (Visual Warning Only):Real-time Stock Validation: Saat kursor berada di input Qty, jika user mengetik jumlah yang melebihi sisa stok produk tersebut, sistem wajib mencegah proses Append.Visual Alert Rule: Jangan gunakan pop-up alert (alert()) atau efek suara. Cukup ubah background input Qty menjadi warna merah pastel lembut, tampilkan teks peringatan kecil berwarna merah di bawah input (contoh: "Stok tidak mencukupi, sisa: 3 Pcs"), dan buat fungsi Enter untuk Append menjadi disabled.Begitu user menurunkan angka Qty sesuai batas stok, warna merah dan teks peringatan langsung hilang secara instan, dan tombol Append kembali aktif.Shortcut Global POS:F8 $\rightarrow$ Memindahkan fokus kursor secara paksa dari mana saja langsung ke input Pencarian Produk.F9 $\rightarrow$ Membuka modal pembayaran atau langsung memindahkan fokus ke input Nominal Uang Bayar.Validation on Pay: Jika metode pembayaran Tunai dipilih dan Nominal Uang Bayar $<$ Total Belanja, tombol "Proses Transaksi" wajib di-disabled untuk mencegah kasir salah input kembalian minus.4. MODULE 6: REKAP PENJUALAN (SALES HISTORY & AUDIT)Modul ini berfungsi sebagai pusat kontrol historis transaksi penjualan yang terjadi di setiap toko.
Fitur Utama & Filter:Sistem wajib menyediakan halaman index rekap penjualan dengan komponen tabel Bootstrap -sm padat informasi, yang dilengkapi komponen Multi-Filter Real-Time/Asynchronous di bagian atas halaman:Filter Rentang Tanggal: Menyediakan input date untuk start date dan end date (Default: menampilkan transaksi hari ini).Filter Nama Pelanggan: Dropdown yang berisi daftar pelanggan toko, termasuk pilihan untuk memfilter transaksi khusus pelanggan "Umum".Filter Status/Metode Bayar: Dropdown pilihan untuk menyaring transaksi berdasarkan tipe pembayaran: Tunai, Kredit, atau Digital Payment.Spesifikasi Tampilan Tabel (table-sm):Kolom rekap wajib menampilkan informasi ringkas: No. Invoice, Tanggal/Waktu, Nama Pelanggan, Total Belanja, Metode Bayar, Status (Lunas/Belum Lunas), Kasir (User), dan Tombol Aksi Cepat (Cetak Ulang Struk / Lihat Detail Transaksi).
5. DATABASE RELATIONAL INTELLIGENCE (Untuk Referensi Agent)Agent harus memastikan integritas data terjaga dengan aturan foreign key berikut:Jika entitas Toko dihapus, maka seluruh data terkait tenant tersebut wajib terhapus secara berantai (ON DELETE CASCADE).Kolom harga pada penjualan_detail wajib merekam harga satuan aktual saat transaksi terjadi (berdasarkan tier harga pelanggan yang aktif), terpisah dari kolom harga di tabel produk, untuk mengamankan data laporan keuangan historis dari efek perubahan harga di masa depan.Backend Price & Payment Validation: Saat transaksi di-submit, backend Laravel wajib memvalidasi ulang harga yang dikirim dari klien dengan mencocokkan database asli berdasarkan status_pelanggan untuk mencegah manipulasi data lewat inspect element browser.
